# Web3 University 产品需求文档（PRD）

> 项目名称：Web3 University（Web3 大学）  
> 文档版本：v1.0  
> 目标网络：Ethereum Sepolia  
> 项目类型：Web3 在线课程 DApp  
> 核心闭环：课程上架 → YD Token 支付 → 链上购买记录 → 完课验证 → NFT 证书

## 1. 项目背景

Web3 University 是一个中心化体验与链上资产结合的在线课程平台。学生使用钱包登录，通过平台发行的 YD Token 购买课程；老师提交课程，Owner 审核并管理上架状态；学生完成课程后，经链下完成状态验证，在链上获得 ERC-721 课程证书。

本项目重点不是把视频、评论等所有内容都存到区块链，而是合理划分链上与链下职责：

- 链上保存课程的关键业务状态、支付记录、权限关系和 NFT 证书。
- 链下保存视频、图片、课程详情、评论、用户名和学习进度等大体量或高频更新数据。
- 链上课程 ID 与数据库课程 ID 保持一致，形成可验证的绑定关系。

## 2. 项目目标

### 2.1 产品目标

1. 实现学生、老师/商家、Owner 三种角色的完整业务流程。
2. 使用 ERC-20 YD Token 完成课程购买。
3. 将课程购买记录和成交价格写入智能合约。
4. 通过链下完成状态验证触发 ERC-721 课程证书铸造。
5. 使用 Privy 提供低门槛登录和嵌入式钱包体验。
6. 提供可在 Sepolia 测试网完整演示的 DApp。

### 2.2 作业演示目标

演示时应能完成以下闭环：

1. Owner 添加一个老师地址。
2. 老师创建并提交课程。
3. Owner 审核并上架课程。
4. 学生登录并领取测试 YD Token。
5. 学生授权 4 YD，并购买课程。
6. 页面显示链上购买记录。
7. 学生完成课程，管理员/预言机确认完成状态。
8. 学生获得对应课程的 NFT 证书。
9. 学生在个人中心查看课程、交易与证书，并通过钱包签名修改用户名。

## 3. 范围定义

### 3.1 MVP 必做范围

- Privy 登录和嵌入式钱包。
- 课程列表、课程详情和课程视频展示。
- 学生、老师、Owner 角色权限。
- 老师提交课程，Owner 审核、上架和下架课程。
- YD Token ERC-20 合约。
- 测试币 Faucet：每个地址领取一次 20 YD。
- 4 YD 课程购买流程：`approve` + `buyCourse`。
- 链上购买状态、成交价格、时间和事件记录。
- 链下评论和学习进度。
- 完课状态提交与 ERC-721 证书铸造。
- 个人中心及签名修改用户名。
- Sepolia 部署和基础错误提示。

### 3.2 加分范围

- 创建一个 Uniswap V3 YD/WETH 测试池。
- 提供从 Uniswap 获取 YD 的外部入口或兑换页面。
- 使用 Chainlink Functions 替换演示用完成状态预言机。
- 使用 The Graph/Subgraph 索引课程购买和证书事件。
- 将课程及 NFT 元数据迁移到 IPFS。

### 3.3 本期不做

- 主网部署和真实资金交易。
- 两个以上 Uniswap 流动性池。
- 自研完整 Swap Router。
- 视频 DRM、防录屏和复杂版权系统。
- DAO 治理、质押、收益分配和代币经济模型。
- 完整退款、争议仲裁和二级 NFT 市场。

## 4. 用户角色与权限

| 角色 | 能力 |
|---|---|
| 游客 | 浏览已上架课程；查看课程介绍；发起登录 |
| 学生 | 领取 YD；购买课程；观看已购课程；评论；更新进度；领取并查看证书；签名修改用户名 |
| 老师/商家 | 拥有学生能力；提交课程；修改未上架或被退回课程资料；查看审核状态 |
| Owner 管理员 | 管理老师白名单；审核、上架、下架课程；确认完课；管理平台关键合约参数 |

角色以钱包地址为身份主体。Owner 和老师权限以合约状态为准，数据库仅缓存显示结果，不作为最终权限依据。

## 5. 核心业务流程

### 5.1 登录与建档

1. 用户点击“登录”。
2. Privy 完成社交账号、邮箱或钱包登录。
3. 系统获得嵌入式钱包或用户外部钱包地址。
4. 后端按钱包地址查询用户；不存在则创建用户记录。
5. 前端读取合约角色并展示对应入口。

### 5.2 课程提交与上架

1. Owner 在管理后台添加老师钱包地址。
2. 老师填写课程名称、描述、封面、视频和价格。
3. 课程详情写入数据库或对象存储，并生成 `metadataURI`。
4. 老师调用合约创建课程，合约生成唯一 `courseId`，初始状态为待审核。
5. 数据库记录绑定同一个 `courseId`。
6. Owner 审核后调用合约批准并上架。
7. 课程进入公开课程列表。

### 5.3 YD Token 获取

MVP 使用 Faucet 保证课堂演示稳定：

1. 学生点击“领取 20 YD”。
2. Faucet 检查该地址是否已领取。
3. 未领取则向学生发放 20 YD，并记录领取状态。
4. 已领取地址不能重复领取。

Uniswap 获取 YD 作为加分路径，不作为购买流程的唯一前置条件。

### 5.4 课程购买

假定课程价格为 4 YD：

1. 学生进入课程详情页。
2. 前端检查钱包网络、YD 余额、授权额度和购买状态。
3. 授权额度不足时，学生调用 YD Token 的 `approve(universityAddress, 4 YD)`。
4. 授权成功后，学生调用 `buyCourse(courseId)`。
5. 核心合约检查课程已上架、未重复购买且余额和授权足够。
6. 合约使用 `transferFrom` 收取 4 YD。
7. 合约记录购买者、课程 ID、实际价格和购买时间。
8. 合约发出 `CoursePurchased` 事件。
9. 页面刷新为“开始学习”。

`approve` 与 `buyCourse` 是两个独立链上交易，界面必须分别显示等待签名、确认中、成功和失败状态。

### 5.5 学习、评论与完课

1. 只有已购买课程的学生可以打开完整视频和课程内容。
2. 视频播放进度和章节完成状态写入数据库。
3. 已购买用户可以发表评论。
4. 完成全部必修章节后，数据库将进度标记为待验证。
5. MVP 由管理员或演示预言机确认该学生已完成课程。
6. 完成状态写入核心合约，并触发证书合约铸造 NFT。
7. 前端展示证书名称、图片、Token ID 和交易链接。

### 5.6 签名修改用户名

1. 登录用户输入新用户名。
2. 后端生成包含钱包地址、新用户名、nonce、过期时间和域名的签名消息。
3. 用户通过 Privy 钱包签名。
4. 后端验证签名、nonce 和过期时间。
5. 验证成功后更新数据库用户名，并使 nonce 失效，防止重放。

## 6. 功能需求

### 6.1 首页

- 展示项目介绍、核心功能、推荐课程和连接钱包按钮。
- 登录后展示钱包缩略地址、网络和 YD 余额。
- 网络不正确时提示切换至 Sepolia。

### 6.2 课程广场

- 仅显示合约中处于已审核且已上架状态的课程。
- 展示封面、名称、老师、价格和购买状态。
- 支持进入课程详情。
- MVP 可仅支持简单分类和关键词筛选。

### 6.3 课程详情

- 展示课程介绍、老师、价格、章节、评论和购买状态。
- 未购买用户只能观看课程预览。
- 已购买用户可以观看完整视频、记录进度和评论。
- 购买按钮根据状态展示：
  - 连接钱包
  - 切换网络
  - 余额不足
  - 授权 4 YD
  - 购买课程
  - 开始学习

### 6.4 老师中心

- 非老师地址不能进入课程提交功能。
- 老师可提交课程及查看自己的课程。
- 展示待审核、已上架、已下架状态。
- 链下资料上传成功但链上交易失败时，应允许重新提交链上交易。

### 6.5 Owner 管理后台

- 添加或移除老师白名单。
- 查看所有待审核课程。
- 审核并上架、拒绝或下架课程。
- 查看待确认的完课申请。
- 调用演示预言机确认完成状态。
- 所有管理交易必须由当前合约 Owner 地址发起。

### 6.6 个人中心

- 展示用户名和钱包地址。
- 支持钱包签名修改用户名。
- 展示 YD 余额、已购课程和学习进度。
- 展示历史购买价格、购买时间和交易哈希。
- 展示已经获得的课程 NFT 证书。

## 7. 智能合约需求

### 7.1 YDToken

标准：ERC-20。

核心能力：

- `name = YD Token`，`symbol = YD`，`decimals = 18`。
- 部署时向指定地址铸造初始供应量。
- 提供符合 ERC-20 标准的余额、授权和转账能力。
- 使用 OpenZeppelin 实现。

### 7.2 YDFaucet

核心能力：

- 每个钱包最多领取一次 20 YD。
- Owner 可向 Faucet 补充 YD Token。
- 发出领取事件。
- Faucet 余额不足时给出明确错误。

### 7.3 Web3University

核心能力：

- 管理老师白名单。
- 创建、审核、上架和下架课程。
- 使用 YD Token 收取课程费用。
- 防止重复购买和未上架课程购买。
- 保存可验证的购买记录。
- 记录课程完成状态。
- 调用证书合约为完成者铸造 NFT。
- 使用访问控制、`SafeERC20` 和重入保护。

建议的链上课程字段：

| 字段 | 说明 |
|---|---|
| `id` | 唯一课程 ID |
| `teacher` | 老师钱包地址 |
| `price` | YD 价格，使用最小单位 |
| `metadataURI` | 链下课程元数据地址 |
| `approved` | 是否通过 Owner 审核 |
| `active` | 是否已上架 |

建议的购买记录字段：

| 字段 | 说明 |
|---|---|
| `student` | 购买者地址 |
| `courseId` | 课程 ID |
| `pricePaid` | 成交时实际支付价格 |
| `purchasedAt` | 区块时间戳 |

### 7.4 CourseCertificate

标准：ERC-721。

核心能力：

- 每个地址对每门课程最多获得一个证书。
- 只有授权的核心合约可以铸造。
- NFT 元数据包含课程名称、学生地址、课程 ID、完成时间和证书图片。
- 发出证书铸造事件。

### 7.5 DemoCompletionOracle

核心能力：

- 仅允许受信任的管理员或后端预言机地址提交完成状态。
- 调用核心合约完成课程确认。
- 防止重复确认与重复铸造。

说明：Chainlink 本身不能直接判断学生是否看完视频。生产方案可以使用 Chainlink Functions 获取可信 API 的完成状态；MVP 使用可替换的演示预言机完成相同接口流程。

## 8. 链上与链下数据设计

### 8.1 链上数据

- Owner 和老师角色。
- 课程 ID、老师地址、价格、元数据 URI、审核和上架状态。
- 学生购买状态、成交价格和购买时间。
- 完课状态。
- ERC-20 余额和授权。
- ERC-721 所有权及 Token URI。
- 关键业务事件。

### 8.2 链下数据

- 用户名、头像和签名 nonce。
- 课程长描述、分类、封面和章节信息。
- 视频 URL 和预览视频 URL。
- 评论内容。
- 每个章节的学习进度。
- NFT 图片和元数据 JSON。

### 8.3 建议数据库表

| 表 | 关键字段 |
|---|---|
| `users` | `wallet_address`, `username`, `avatar_url`, `signature_nonce` |
| `courses` | `course_id`, `teacher_address`, `title`, `description`, `cover_url`, `metadata_uri` |
| `lessons` | `id`, `course_id`, `title`, `video_url`, `sort_order`, `is_preview` |
| `comments` | `id`, `course_id`, `wallet_address`, `content`, `created_at` |
| `progress` | `wallet_address`, `course_id`, `lesson_id`, `percent`, `completed_at` |
| `completion_requests` | `wallet_address`, `course_id`, `status`, `verified_at`, `tx_hash` |

钱包地址统一转为小写保存，并对关键组合字段建立唯一约束。

## 9. 事件与查询需求

核心合约至少发出以下事件：

- `TeacherUpdated(teacher, enabled)`
- `CourseCreated(courseId, teacher, price, metadataURI)`
- `CourseApproved(courseId)`
- `CourseStatusChanged(courseId, active)`
- `CoursePurchased(student, courseId, price, purchasedAt)`
- `CourseCompleted(student, courseId, completedAt)`
- `CertificateMinted(student, courseId, tokenId)`
- `TokensClaimed(student, amount)`

MVP 可通过合约读取和事件查询展示当前用户数据。The Graph 仅作为数据量增大后的可选索引层。

## 10. Uniswap 与 Chainlink 方案

### 10.1 Uniswap

MVP 使用 Faucet 提供稳定测试路径。加分版本创建单一 YD/WETH Uniswap V3 池：

- 使用 Sepolia 测试代币和测试 ETH。
- 项目页面提供池地址和 Uniswap 跳转入口。
- 不承诺代币真实价值。
- 不把 Uniswap 是否有流动性作为课程购买成功的必要条件。

如需 USDC 演示，优先部署并明确标注 `MockUSDC`，避免用户误认为真实 USDC。

### 10.2 Chainlink

MVP 使用 `DemoCompletionOracle`。后续可用 Chainlink Functions：

1. 核心合约或自动化流程发起完成状态请求。
2. Chainlink Functions 请求平台后端 API。
3. API 返回指定学生和课程的完成状态。
4. DON 返回结果并执行合约回调。
5. 合约验证结果后铸造证书。

## 11. 非功能需求

### 11.1 安全性

- 合约使用 OpenZeppelin 标准实现。
- 管理函数必须具有严格访问控制。
- Token 转账使用 `SafeERC20`。
- 外部调用遵循 Checks-Effects-Interactions，并使用重入保护。
- 防止重复购买、重复领取 Faucet 和重复铸造证书。
- 用户名签名必须包含 nonce、过期时间和应用域，防止重放及跨站复用。
- 私钥、数据库密钥和服务端密钥不得提交到 GitHub。

### 11.2 可用性

- 所有链上操作均显示当前阶段和交易哈希。
- 用户拒签、余额不足、授权不足、网络错误和交易回滚时给出中文提示。
- 钱包地址使用缩略显示，并提供复制和区块浏览器链接。
- 页面刷新后能从链上和数据库恢复正确状态。

### 11.3 性能

- 课程列表首屏在常规网络下应尽快展示骨架和基础信息。
- 视频、图片采用懒加载。
- 不在单次请求中扫描无限范围的链上事件。

## 14. 验收标准

### 14.1 核心验收

- [ ] 用户可以通过 Privy 登录并获得钱包地址。
- [ ] 应用能识别当前钱包的学生、老师或 Owner 角色。
- [ ] Owner 可以添加老师。
- [ ] 老师可以提交包含链下资料的课程。
- [ ] Owner 可以批准并上架课程。
- [ ] 上架课程能出现在课程列表中。
- [ ] 学生每个钱包只能领取一次 20 YD。
- [ ] 学生可以先授权 4 YD，再购买课程。
- [ ] 合约能够阻止未上架课程及重复购买。
- [ ] 页面可以展示购买价格、时间及交易哈希。
- [ ] 未购买用户不能访问完整课程内容。
- [ ] 已购买用户可以记录进度并发表评论。
- [ ] 完课确认后，学生获得唯一课程 NFT 证书。
- [ ] 个人中心能够显示已购课程、进度和证书。
- [ ] 修改用户名需要有效的钱包签名，旧签名不可重放。
- [ ] 合约及前端部署在 Sepolia 环境可完整演示。

### 14.2 异常验收

- [ ] 非 Owner 无法调用管理功能。
- [ ] 非老师无法提交链上课程。
- [ ] YD 余额或授权不足时购买失败并显示原因。
- [ ] 用户拒签时页面不会错误地显示成功。
- [ ] 数据库写入失败时不会伪造链上成功状态。
- [ ] 相同学生和课程不能重复铸造证书。

## 15. 开发里程碑

### 里程碑一：合约闭环

- 建立 Foundry 工程。
- 完成 YDToken、YDFaucet、Web3University、CourseCertificate 和 DemoCompletionOracle。
- 编写权限、购买、重复操作和证书测试。

## 17. 风险与应对

| 风险 | 应对方式 |
|---|---|
| Sepolia 测试币不足或网络拥堵 | 提前准备测试账户和测试 ETH；保留本地链演示方案 |
| Uniswap 池缺少有效流动性 | Faucet 作为稳定主路径，Uniswap 仅做加分项 |
| Chainlink 配置时间过长 | 使用同接口的 DemoCompletionOracle，并明确说明生产替换方案 |
| 链上与数据库课程 ID 不一致 | 链上生成 ID 后再写数据库，并设置唯一约束 |
| 两笔购买交易让用户困惑 | 明确展示“授权”和“购买”两个步骤及状态 |
| 视频直接公开 URL 被绕过 | 本作业只做购买权限控制；生产环境使用短期签名 URL |
| 环境变量泄露 | 提供 `.env.example`，将真实 `.env` 加入 `.gitignore` |
