# Owner 后台 — 需求规格

## 概述

实现 Owner 管理后台页面：课程审核队列、老师白名单管理、完课确认与证书铸造操作入口，均为前端 Mock 交互。

## 项目信息

- 项目名: web3-university
- 架构类型: 单体仓库：Next.js 前端（纯 UI + Mock 交互）

## 需求版本

| 日期 | 版本 | 说明 |
| --- | --- | --- |
| 2026-08-12 | v1 | 初始需求 |

## 用户故事

- 作为 Owner，我想要查看待审核课程列表并批准/拒绝，以便控制平台课程质量。
- 作为 Owner，我想要管理老师白名单（添加/移除），以便控制谁可以提交课程。
- 作为 Owner，我想要查看学生完课申请并触发证书铸造，以便完成教学闭环的最后一步。

## 功能需求

1. [F-001] 后台布局：侧边栏导航（概览/老师管理/课程审核/完课确认/设置），顶部沿用全局 `TopNav`。
2. [F-002] 课程审核队列：展示待审课程列表（课程名、老师地址、描述摘要），提供"通过"/"拒绝"操作，点击后 Mock 更新课程状态。
3. [F-003] 老师白名单管理：表格展示（钱包地址、添加时间、状态、删除操作）+ 新增老师表单（输入地址后 Mock 新增一条记录）。
4. [F-004] 完课确认：展示学生地址 + 课程 + 完成状态列表，提供"铸造 NFT"操作按钮，点击后 Mock 触发铸造中状态提示。
5. [F-005] 管理表格通用样式：无竖线、仅细横向分隔线，表头使用 JetBrains Mono，供审核队列/白名单/完课确认三处表格复用。
6. [F-006] 权限提示占位：页面顶部或指定位置展示"仅 Owner 可操作"的 Mock 提示文案（不做真实地址校验，纯 UI 展示）。

## 非功能需求

- 性能: 无特殊要求。
- 安全: 页面本身不做真实链上 Owner 地址校验；文案需明确标注当前为演示模式。
- 兼容性: 侧边栏在移动端应可折叠为顶部下拉或抽屉菜单，表格在小屏下可横向滚动或转卡片式。

## 验收标准

- [ ] [AC-001] 页面结构与 Stitch 截图一致（侧边栏 + 课程审核 + 老师白名单 + 完课确认三大功能区）。
- [ ] [AC-002] 点击待审课程"通过"后，该课程从待审列表移除（或状态更新为已上架，二选一并在 design.md 中明确）。
- [ ] [AC-003] 新增老师地址后，表格中出现对应新记录。
- [ ] [AC-004] 点击"铸造 NFT"后展示铸造中的 Mock 状态反馈（如按钮 loading 态或提示文案）。
- [ ] [AC-005] 三处表格样式统一（无竖线、细横向分隔线、JetBrains Mono 表头）。
