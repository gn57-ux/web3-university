# 课程广场 — 需求规格

## 概述

实现课程广场页面：搜索与难度筛选、课程卡网格展示，基于 Stitch 设计稿还原，数据全部为前端 Mock。

## 项目信息

- 项目名: web3-university
- 架构类型: 单体仓库：Next.js 前端（纯 UI + Mock 交互）

## 需求版本

| 日期 | 版本 | 说明 |
| --- | --- | --- |
| 2026-08-12 | v1 | 初始需求 |

## 用户故事

- 作为访客/学生，我想要浏览所有已上架课程，以便发现感兴趣的学习内容。
- 作为访客/学生，我想要按关键词或难度筛选课程，以便快速定位目标课程。

## 功能需求

1. [F-001] 页面 Hero：标题「掌握最新的区块链技术、智能合约开发和去中心化金融原理」+ 副文案 + 搜索框 + 难度筛选 Tabs（全部/初级/中级/高级）。
2. [F-002] `CourseCard` 组件：封面图、难度徽标、标题、讲师（含图标）、价格（YD）、报名人数（含图标）。
3. [F-003] 课程网格：至少 3 门 Mock 课程（如「Solidity 智能合约入门」「从零构建 Web3 DApp」「DeFi 与 Uniswap 实战」），字段遵循 feature 1 的 `Course` 类型。
4. [F-004] 搜索框输入关键词与难度 Tab 选择，纯前端过滤课程列表，无接口请求。
5. [F-005] 筛选结果为空时展示空状态提示；首次加载展示骨架屏（Mock 场景下可用短暂延时模拟）。
6. [F-006] 点击课程卡跳转至对应课程详情页路由（`/courses/{id}`）。

## 非功能需求

- 性能: 客户端过滤应在输入时即时响应（无防抖也可接受，因数据量小；如引入防抖需说明理由）。
- 安全: 无。
- 兼容性: 网格列数随断点变化（桌面多列、平板/移动按设计系统列数收窄）。

## 验收标准

- [ ] [AC-001] 页面初始展示全部 Mock 课程，卡片信息与 Stitch 截图字段一致。
- [ ] [AC-002] 搜索关键词后仅展示标题/讲师匹配的课程。
- [ ] [AC-003] 切换难度 Tab 后仅展示对应难度课程，且可与搜索关键词叠加生效。
- [ ] [AC-004] 筛选结果为空时展示明确的空状态提示，不显示空白网格。
- [ ] [AC-005] 点击任意课程卡正确跳转到 `/courses/{id}`。
