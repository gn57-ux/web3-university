**问题/场景**：老师工作台的"提交新课程"表单同时承担"新建课程"和"编辑已有课程"两种用途。表单原本无论哪种用途，都要求在"保存草稿"（→ `draft`）与"提交审核"（→ `pending`）之间二选一——这对新建课程、或编辑一门本来就是草稿的课程没问题，但编辑一门**已上架**（`active`）的课程时，同一个表单会把它的状态覆盖成 `draft`/`pending`，导致这门已上架课程从"已上架"列表消失、丢失学生进度等展示字段，是一个真实的状态机缺陷（不是视觉问题，是数据被错误改写）。

**解法/结论**：表单/弹窗组件增加一个"锁定状态"模式——编辑一个已经不处于"表单默认可选状态集合"（这里是 draft/新建）的实体时，只提供一个"保存修改"按钮，只更新内容字段，不触碰状态字段；只有新建、或编辑本就在可选状态集合内的实体时，才展示完整的状态切换按钮组。

**复用方式**：任何"新建"和"编辑"共用同一个表单/弹窗的场景，设计前先列一张表——这个实体有哪些状态，每个状态下"编辑"应该允许做什么操作、不允许做什么。不能默认"编辑态和新建态的可选操作集合完全一样"，尤其是表单原本设计的按钮组（如状态切换类按钮）很可能只对"新建"或"某个特定初始状态"有意义，编辑其它状态的实体时需要单独处理，而不是直接复用整套按钮。
